## 根目录维护入口

使用装好对应依赖的 Python；维护入口本身只需要标准库，不会取行情或下单。

```bash
python3 project.py inventory
python3 project.py doctor --suite rotation
python3 project.py test --suite rotation
python3 project.py doctor --suite single
python3 project.py test --suite single
```

`doctor` 仅检查模块存在，不证明版本兼容或 Wind 已连接。`test` 调用既有测试，失败返回非零状态；两套测试在独立进程中运行。现有取数和回测命令见各模块 README，其中组合 README 的旧绝对路径已过时，应以本仓库路径为准。

本轮实测：组合在已有 Python 3.12.14 研究环境通过 48 项测试；单资产在其本地 `.venv` 通过 14 项测试，共 62 项。组合测试有 378 条 sklearn 缺观测特征警告，来自短历史测试样本的填补过程，需在工程化时明确特征可用规则。未重新取行情、重跑完整历史绩效或验证实盘连接。

## 工程缺口

1. **目录与版本管理。** 源码、行情、报告、代码快照及第三方参考混在 `outputs/`。盘点时 `git ls-files` 为空，现有内容尚未纳入 Git 跟踪；应先建立可复现基线，明确行情、环境和结果的归档规则，再迁移源码。当前整理未删除、移动或提交任何研究记录。
2. **运行与配置。** 缺根级 `pyproject.toml`、统一 CLI 和统一配置模型。平层、自适应、预测及部分基准入口固定读取 `20260924` 行情；批量比较和报告脚本绑定实验目录。新数据到来不会自动贯通整个流程。
3. **数据服务。** 单资产已有 Wind 优先、超时、备用源和失败记录；组合 `wind_fetch.py` 当前仍是 Wind 专用入口，未统一接入主备服务。不可直接复用 OHLCV 适配器替代中债财富指数、EDB 现金或指数估值，须分别定义适配与校验。
4. **运行可复现性。** 部分运行记录已有配置和数据/代码哈希，但还缺统一的完整代码版本、依赖环境、随机种子和实验身份；已有旧结果也可能早于当前算法修改。应检查“当前代码与结果对应关系”，不能仅依据报告文件日期。
5. **持续运行。** 回测中的账户对象及 `open_position.json` 不等于可恢复的实盘账户。缺持续账本、订单状态、成交对账、幂等处理、重启恢复和市场日历驱动。
6. **统一验收。** 测试覆盖数学、时序及部分取数行为；缺贯穿取数到报告的集成验收、统一数据新鲜度检查和故障退出约定。未设置 CI。
7. **状态输出。** 单资产已有 `NOT_VALIDATED` 等状态，组合也有目标评价；尚未统一成固定机器状态与原因码。历史诊断和文字报告不能代替正式通过/拒绝输出。

## 可以彻底程序化的流程

取数 → 校验 → 数据快照 → 特征/预测 → 配置或交易信号 → 执行模拟 → 账户更新 → 指标与验收 → 报告，均可由确定的程序执行。论文检索和方法选择属于研发阶段，不应成为日常运行必需步骤；日常运行不需要语言模型读取图表、解释结果或决定是否交易。

| 工作 | 程序化方式 | 失败处理 |
| --- | --- | --- |
| 数据更新 | Wind 优先；失败后按资产调用备用源；记录区间、时间、口径及来源 | 无有效真实数据则停止本次正式运行；保留旧快照但不冒充新数据 |
| 数据校验 | 日期、重复、空值、复权、币种、交易日历、覆盖范围、可用时点 | 输出固定错误码，禁止静默补造数据 |
| 运行 | 配置指定策略 ID、版本、输入、参数、时间范围、成本与种子 | 参数不全或不兼容则拒绝；不自动放松回撤约束 |
| 比较验收 | 固定训练/验证规则；统一现金超额、回撤与成本压力检查 | 无达标策略时输出空候选和原因，不强选一个 |
| 报告 | 从同一次运行的结构化输出生成图表与摘要 | 禁止混用其他实验目录的净值或仓位 |
| 纸面交易 | 交易日历触发、信号持久化、模拟成交、对账与状态恢复 | 重复运行不重复成交；数据过期禁止生成可执行订单 |

预测、配置和模拟已经大部分写好，主要工作是接口统一和工程补齐。实际下单还需要专门的执行适配；中债指数必须映射实际产品，不能直接变成订单。

## 建议的程序结构与实施顺序

目标结构：`src/riskparity/{data,signals,strategies,backtest,portfolio,validation,reporting}`，配合 `configs/`、`tests/`、`research/`、`data/`、`runs/`。第三方参考留在研究归档，生产入口不导入报告快照。

**第一阶段：可复现研究程序。** 固定当前代码与数据基线；提取公共数据、现金、成本和回测接口；注册 ERC、分层、平层、自适应等明确策略 ID；所有入口支持外部数据路径和配置；增加根级安装与 CLI。验收：一条命令从指定离线快照生成完整结果，不依赖 AI、旧工作目录或手工改源码。先保持已有数学和时序规则，核对迁移前后结果。

**第二阶段：无人值守研究流水线。** 统一 Wind 主备取数与来源审计；加入数据新鲜度与可用时点检查；完成运行清单、状态码、日志、集成测试及 CI。验收：一次运行成功给出完整结果；取数失败、空数据、数据过期、求解失败和无合格策略均能自动输出明确失败或拒绝状态。

**第三阶段：持续纸面交易程序。** 增加账户与订单账本、幂等及重启恢复、真实报价/复权转换、整数份额与成交限制、对账。验收：交易日历驱动运行，重复触发和中断恢复不改变账本，净值可逐日核对。

**第四阶段：实际执行适配。** 在冻结规则的纸面交易和策略验收之后接券商接口。期货另补合约主数据、换月、保证金、夜盘与收费规则。软件工程通过不能自动将策略状态改为可实盘。

最先完成第一、二阶段，才是本项目从“需要 AI 串联脚本”变为独立程序的关键。UI、更多论文和更多模型不应成为这两阶段的前置工作。
